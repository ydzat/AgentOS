# AOS 微内核架构 / Microkernel Architecture

## 架构总览

```
┌─────────────────────────────────────────────┐
│                  用户层                       │
│  PersonalAgent（用户的代理身份）               │
│  应用 Agent · 工具 Agent · 协作 Agent         │
├─────────────────────────────────────────────┤
│              用户态服务                       │
│  推理引擎 · 记忆文件系统 · 设备驱动            │
│  AgentPack 模块系统 · AOS Hub                │
├─────────────────────────────────────────────┤
│              AOS 微内核 (Rust)                │
│  Agent 生命周期 · IPC · Capability 管控       │
│  资源预算执行 · 中断/异常 · 最小内存管理        │
├─────────────────────────────────────────────┤
│              硬件                            │
│  CPU · GPU/NPU · 传感器 · 执行器 · 存储       │
└─────────────────────────────────────────────┘
```

## 微内核职责

内核只负责**机制（mechanism）**，不包含任何**策略（policy）**：

| 职责 | 说明 |
|------|------|
| Agent 生命周期管理 | 创建 / 销毁 / 挂起 / 恢复 |
| IPC（进程间通信） | Agent 间消息传递的唯一通道 |
| Capability 权限管理 | Agent 能调用哪些 Tool，由内核强制执行 |
| 资源预算强制执行 | 算力 / 内存 / Token 配额的硬限制 |
| 中断与异常处理 | 基础硬件抽象 |
| 最小内存管理 | 页表、地址空间隔离 |

## 不在内核中的组件

以下全部运行在用户态：

| 组件 | 说明 |
|------|------|
| 推理引擎 | 模型加载与推理执行，崩溃可由内核重启 |
| 记忆文件系统 | Agent 记忆的持久化存储与检索 |
| 设备驱动 | GPU/NPU/传感器/执行器的用户态驱动 |
| AgentPack 模块管理 | 模块的下载、安装、依赖解析 |
| 网络栈 | 用于远程推理、Agent 间跨机通信 |

## 推理引擎与内核的关系

```
方案（已选定）: 推理引擎在用户态

┌─────────┐
│ Agent   │
├─────────┤
│ 调度/IPC │ ← 内核只做调度
├─────────┤
│ 推理引擎 │ ← 特权用户态，崩溃可恢复
├─────────┤
│ 内核    │
├─────────┤
│ 硬件    │
└─────────┘
```

设计理由：
- 推理引擎是"策略"，不是"机制"，不属于内核
- 推理服务崩溃不会拖垮系统，内核可以安全重启
- 推理后端可替换（本地模型 / 云端 API / 专用 NPU），无需改内核

## 推理模式

AOS 支持三种推理模式，由用户态推理服务配置决定，内核不关心：

| 模式 | 描述 | 适用场景 |
|------|------|---------|
| 本地推理 | 用户态驱动访问 GPU/NPU，运行量化模型 | 桌面/工作站 |
| 远程推理 | 推理请求卸载到云端 API | 边缘设备、嵌入式 |
| 混合推理 | 本地小模型做快速决策，复杂任务卸载远程 | 机器人、通用 |

## 内存模型

**决策：每个 Agent 拥有独立地址空间（独立页表）。**

### 推导依据

正向（从硬件）：
- MMU 提供硬件级页表隔离，无法绕过
- 独立地址空间的上下文切换开销（~1-5μs TLB 刷新）对 Agent 可接受

反向（从应用）：
- Agent 可能来自不受信任的 AOS Hub → 必须硬件级隔离
- Agent "思考"时主要等推理结果（I/O 密集）→ 切换频率不高，TLB 开销可接受
- Agent 间通信是语义化消息，不是原始内存共享 → 不需要零拷贝

## 人机接口（Human Interface）

人机接口是**内核组件**，不是 Agent，确保人类始终拥有对系统的最终控制权。

设计要求：
- 独立于 Agent 子系统运行，Agent 崩溃不影响人机接口
- Agent 无法截获、篡改、阻断人类的指令
- 提供委托链管理——所有 Agent 权威可追溯到人类
- 提供行为审计——人类可随时查看任何 Agent 的行为记录
- 提供紧急终止——人类可随时停止任何或全部 Agent

## 文件系统布局

```
/
├── home/                      # 用户主目录
│   ├── alice/
│   │   ├── documents/         # 用户文件（论文、数据等）
│   │   ├── config/            # 个人配置
│   │   └── ...
│   └── bob/
│
├── sys/                       # 系统核心
│   ├── agents/                # 系统级 Agent（safety, init）
│   ├── config/                # 系统配置
│   ├── drivers/               # 驱动
│   └── models/                # 模型权重
│
├── apps/                      # 已安装的 AgentPack / 应用
│   ├── data-analyzer/
│   └── paper-reviewer/
│
├── memory/                    # Agent 记忆存储
│   ├── alice/                 # 按用户隔离
│   │   ├── short/
│   │   └── long/
│   └── shared/                # 跨 Agent 共享记忆
│
├── var/                       # 运行时可变数据
│   ├── log/                   # 日志
│   ├── cache/                 # 缓存
│   └── tmp/                   # 临时文件
│
└── dev/                       # 设备文件
```

### 命名约定

沿用开发者熟悉的 Linux 传统命名，降低认知负担：

| AOS | Linux 对应 | 说明 |
|-----|-----------|------|
| `/home/` | `/home/` | 通用约定 |
| `/sys/` | `/usr/` + `/etc/` | 系统相关 |
| `/apps/` | `/opt/` + `/usr/bin/` | 已安装应用 |
| `/memory/` | 无对应 | AOS 独有，Agent 记忆持久化 |
| `/var/` | `/var/` | 通用约定 |
| `/dev/` | `/dev/` | 通用约定 |

### 数据归属原则

- `/home/alice/` 属于人类用户 alice，Agent 需被委托才能访问
- `/memory/alice/` 是 alice 的 Agent 记忆，按用户隔离
- `/apps/` 中安装的 AgentPack 不能自动获得用户数据访问权，必须人类显式授权

## 目标硬件平台

| 场景 | 最低配置 |
|------|---------|
| 开发/调试（QEMU） | x86-64 / ARM64, 4 核, 32GB RAM, 8GB VRAM GPU |
| 边缘/嵌入式 | ARM / RISC-V + 专用 NPU, 512MB-2GB RAM |
| 机器人平台 | ARM64 + NPU, 8GB+ RAM, 实时传感器接口 |
