# AOS 设计哲学 / Design Philosophy

## 核心命题

传统操作系统的核心假设是"人坐在机器前操作"。AOS 的核心假设是：

> **执行者是 AI Agent，而非人类编写的程序。**

## 定位

AOS 是一个独立的操作系统内核，与 Linux/macOS/Windows 并列——不是运行在它们之上的中间件。

| 传统 OS | AOS |
|---------|-----|
| 核心抽象：进程 + 文件 | 核心抽象：Agent + 记忆 |
| 调度资源：CPU 时间片 | 调度资源：推理算力 + Token 预算 |
| 安全模型：用户/组/权限位 | 安全模型：Capability-based |
| 交互模式：人 → 程序 → 结果 | 交互模式：人 → 意图 → Agent 自主执行 |

## 第四类操作系统

| OS 类别 | 核心抽象 | 设计假设 |
|---------|---------|---------|
| Unix/Linux | 进程 + 文件 | 人写程序，程序处理数据 |
| Windows/macOS | 窗口 + 应用 | 人通过 GUI 操作应用 |
| RTOS | 任务 + 时限 | 硬件控制回路必须确定性响应 |
| **AOS** | **Agent + 记忆** | **AI Agent 自主执行，人表达意图** |

## 一句话定位

> **Agent 即进程，推理即计算，记忆即文件系统。**

## "Agent 即用户"

AOS 最激进的设计理念：PersonalAgent 是用户在系统中的常驻代理身份。

- 用户不直接操作系统，PersonalAgent 代替用户操作
- PersonalAgent 理解用户偏好、习惯和目标
- 用户不在场时，PersonalAgent 持续工作
- 多个 PersonalAgent 可互相协作，形成组织级协作

## 技术选型

- **内核语言**: Rust（内存安全、零开销抽象、并发安全）
- **内核架构**: 微内核（最小内核 + 用户态服务）
- **目标架构**: x86-64 / ARM64（初期），RISC-V（计划中）
- **引导方式**: UEFI

### 为什么选 Rust？

1. **内存安全** — Ownership 模型在编译期消除 use-after-free、data race，这是长期运行的 Agent 系统最致命的 bug 类型
2. **零开销抽象** — 性能与 C 相当，但可以安全地构建更复杂的抽象（trait、泛型）
3. **并发安全** — `Send`/`Sync` trait 让编译器检查并发安全，在内核级别极其宝贵
4. **生态成熟** — Redox OS、Asterinas 已证明 Rust 写内核可行
5. **无隐式开销** — 没有 C++ 的隐式拷贝/析构/异常，代码行为可预测

### 为什么选微内核？

1. **推理引擎可替换** — 今天 llama.cpp，明天云端 API，后天专用 NPU，内核不用改
2. **故障隔离** — 推理服务崩溃，内核重启它即可，不会导致系统崩溃
3. **硬件解耦** — 同一内核可跑在树莓派（远程推理）、桌面（本地 GPU）、数据中心（集群推理）

## 设计参考

| 项目 | 参考价值 |
|------|---------|
| Redox OS | Rust 微内核 OS 先驱 |
| Asterinas | Rust 生产级 Linux 替代方案 |
| seL4 | 形式化验证微内核，Capability 安全模型 |
| OpenClaw | 应用层验证了 Agent 自主协作的可行性 |

### OpenClaw 的启示

OpenClaw 在应用层（Node.js + Linux）证明了 Agent 自主协作的需求是真实的。但它也暴露了应用层方案的天花板：

- Agent 间通信经过 WebSocket + Linux 网络栈，延迟高
- 安全隔离依赖应用层检查，可绕过
- 资源限制靠自律，无法强制执行

AOS 的价值：当 Agent 协作从应用层下沉到内核，释放实时性、安全性、物理世界交互方面的可能性。

## 备选目标平台：机器人

机器人是 AOS 的天然目标平台之一：

- 机器人不需要人坐在屏幕前 → Agent 即用户的设计天然契合
- 多子系统协同（感知、规划、运动、安全）→ 多 Agent 协作
- 实时性要求 → 内核级 IPC 的微秒级延迟优于 ROS 的中间件方案
- 安全约束 → Capability + Safety Agent 提供硬件级保障
